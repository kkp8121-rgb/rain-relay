## Design

**RAIN RELAY · 꽃들이 비를 기억하는 법**. Genre: 3D garden automation puzzle. Hook: **빗방울에 꽃의 빛을 섞어, 메마른 정원을 스스로 피어나게 만든다.** Theme: water remembers its connections. A droplet accumulates red/green/blue light from fixed flowers. The player builds an actual pipe network to supply the correct light mixture to collector flowers. Splitting alternates droplets; crossing pipes keep streams separate. No decorative color mechanic and no forced wins.

Root compared seasonal ecology simulation, orbital navigation and garden automation. The automation puzzle adds a different goal, input family, camera and progression: design first, observe autonomous packets, identify a leak or incorrect mixture, edit and run again. Six authored gardens introduce straight/elbow routing, light addition, branching and crossings. Finite parts budget, finite source water and visible receiver quotas. Failed tests retain the network. Free undo in edit, optional hint reveals one missing authored piece and affects grade. No reaction timer during planning.

Original adults: Nara32, botanist with dark aubergine bob, hazel eyes, sage work apron over cream practical high-neck shirt, rolled sleeves and brass lens pendant; Iris61, olive-skinned greenhouse keeper with grey curls and rust shawl; Yul26, tan freckled canal courier with short dark hair and teal rain jacket; Dae44, broad-faced irrigation engineer with dark greying beard and navy work vest. Portrait atlas even2×2 Nara TL/Iris TR/Yul BL/Dae BR. Gardens1–2 Iris,3–4 Yul,5–6 Dae. Root provides original key-art.webp and portraits.webp. Core play models flowers, channels, valves, collector petals and droplets in a small greenhouse diorama. No robot or borrowed pinball/court models.

## Shared grid and data

7×7 square grid. Cells x,z integers0..6. Index=z*7+x. Directions0=N(z-1),1=E(x+1),2=S(z+1),3=W(x-1). Opposite=(dir+2)%4. World X=(x-3)*1.25; world Z=(z-3)*1.25; terrain playing topY=0. Pipe flow height≈.22; bridges physically separate north/south upper channel from east/west lower channel. Fixed orthographic isometric overview, no arena movement or camera control.

data.js exports deep-frozen LEVELS, RULES, PIECES, COLORS, getLevel(id), ports(kind,rot), indexOf(x,z). RULES includes gridSize7,cellSize1.25,tickSeconds.32,sourceIntervalTicks2,leakLimit3,maxTicks100. Colors bit masks:0 clear dew/맑은 이슬 (pale cyan outline),1 red/붉은빛,2 green/초록빛,4 blue/푸른빛,3 yellow/노란빛,5 magenta/자홍빛,6 cyan/청록빛,7 pearl white/별빛. Add light by bitwise OR, never mixing pigment. Display Korean names, not bit numbers as product copy.

Placeable PIECES in tool order (keys1–4): straight(cost1,ports[rot,(rot+2)%4]); elbow(cost1,ports[rot,(rot+1)%4]); splitter(cost2,INPUT ONLY opposite(rot), OUTPUT alternating (rot+3)%4 then (rot+1)%4); bridge(cost3,portsall4,output opposite incoming). Pipe ports must actually connect; empty cells and wrong ports leak. Bidirectional straight/elbow accept either port and output the other. A bridge carries crossing streams independently and does not mix their light. A splitter conserves droplets: alternates one output per arrival, NEVER clones water. Its counter resets for each run.

Fixed tile schema `{x,z,kind:'source'|'flower'|'sink'|'rock',rot,mask?,need?}`. Source outputdir=rot, initialmask0. Flower accepts ONLY inputopposite(rot), adds mask, outputs rot. Sink mouthdir=rot (i.e. accepts an arriving packet whose incoming port equals rot), requires exact mask, need quota. Full sinks absorb further correctly colored droplets without leaking or overcounting. Rocks have no ports. Fixed tiles cannot be overwritten, erased or rotated. Source also rejects incoming packets. Placeable board entries `{kind,rot}` or null, fixed entries copied withfixedtrue. Guard edges and budget using actual total cost. Replacement refunds oldpiece in cost calculation; rejected actions must be inert. Undo restores exact preceding edit; no history or score forgery.

Each LEVEL schema `{id,title,owner,ownerAge,portraitIndex,intro,outro,budget,par,supply,fixed:[...],solution:[{x,z,kind,rot}],unlockedTools:[...],requirements:[{x,z,mask,need}]}`. Requirements can derive from sinks rather than duplicated divergent values. Solutions are authored help/solvability data, not used to drive simulation. Root provides exact paths below; convert each empty path tile to matching ports. Shared crossings require bridge, authored branch points require splitter. Calculate par from actual solution cost and validate rather than guessing. A path includes fixed source/flower/sink nodes but solution excludes them. Use no additional obstacles on a listed path. Optional rocks specified below only.
